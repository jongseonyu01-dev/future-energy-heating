# 기사 매출·결제수단·본사 수금관리 read-only 조사 — 2026-09-16

## 운영 본사 화면 확인

- 공식 본사 관리자 화면: `https://퓨처에너지테크.kr/web/admin/dashboard.html`
- 본사 관리자 세션에서 `수금관리` 메뉴가 실제로 표시됨을 확인했다.
- 대시보드의 현재 월 완료 작업 수는 25건으로 표시됐다. 이 값은 완료 접수 현황일 뿐, 매출·실제 입금액과 동일한 값으로 취급하지 않는다.
- 이 단계에서는 데이터 수정·삭제·고객 매출 생성·문자 발송을 하지 않았다.

## 운영 소스에서 확인된 기존 기준

- `work_reports.paymentMethod`, `work_reports.paymentAmount`는 nullable 결제 필드로 존재한다.
- 기사 월별 집계는 `isCompleted=true`와 `completedAt`의 한국시간 월 시작 이상·다음 달 시작 미만 조건을 사용하며, 집계 금액은 `paymentAmount`다.
- 본사 수금 달력은 기사 완료보고의 `grossAmount`와 본사 확정 `actualDepositAmount`를 별도로 보관한다. `workReportId`는 본사 ledger에서 고유 키로 처리된다.
- 따라서 견적금액·기사 보고 수금액·본사 실제 입금액을 동일한 값으로 강제하거나 추정해서는 안 된다.

## 운영 수금관리 화면 read-only 대조

본사 관리자 세션에서 2026년 9월 수금관리 화면을 읽기 전용으로 조회했다. 기사 완료보고를 원천으로 한 본사 매출 달력에는 **총매출 2,901,001원**, **실제 입금 0원**, **카드 매출 710,000원**, **계좌이체 매출 2,191,001원**, **현금 매출 0원**이 표시됐다. 이 값은 수금관리 화면이 매출과 본사 확인 실입금을 분리해 유지하고 있음을 확인하는 근거이며, 기사·고객별 상세 정보는 이 증빙에 기록하지 않는다.

동일 화면의 기사 완료보고 월별 수금 현황은 **25건, 2,901,001원**으로 표시됐으며, `미입력`, `기타`, `계좌이체`, `카드` 결제수단별 분리가 확인됐다. 반면 별도 수금관리 목록은 당시 0건으로 표시됐다. 따라서 운영 데이터 자체가 전부 사라진 것이 아니라, 기사앱의 결제 입력·월간 집계 화면과 별도 수금 목록은 서로 다른 기존 흐름임을 확인했다. 이 조회에서는 어떤 입금확인·세금계산서·수금 항목도 변경하지 않았다.
